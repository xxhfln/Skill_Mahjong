# 技能麻将 · 技能卡抽取

提供两种模式（顶部导航切换）：

- **单机模式**：在自己设备上随机抽 N 张技能卡、打出、重置。无需联网、无需服务器。
- **房间模式**：一人开房、多人联机（2–4 人）。房主配置共享技能池与每人抽卡数，各自抽卡，卡面在「使用」前对他人保密，房主可一键重置开新局。

## 1. 单机模式（最快上手）

不需要任何后端，直接用静态服务器打开即可：

```bash
python3 -m http.server 5173
```

浏览器打开 `http://localhost:5173`，切到「单机」标签使用。
（微信内置浏览器、手机浏览器同样可用；微信缓存重请见文末「微信打不开最新版」一节。）

## 2. 房间模式 · 本机

房间模式需要一个 WebSocket 房间服务。本仓库自带，Node 即可运行：

```bash
npm install      # 安装依赖（仅需一次，已装 ws）
npm start        # 启动服务，默认监听 http://localhost:3000 与 ws://localhost:3000/ws
```

打开 `http://localhost:3000`：

1. 切到「房间」标签。
2. **建房**：填昵称 → 勾选本局共享技能池 → 设定每人抽卡数 → 点「创建房间」。
3. 建房成功后页面顶部显示**房间码**，把房间码发给同机的其他浏览器 / 设备即可加入。
4. 其他人点「加入房间」、输入房间码与昵称即可入房。
5. 各自点「抽卡」→ 抽到后点卡面「使用」才会向全员公开。

> 服务器会在返回首页时自动把当前访问地址写进页面，因此本机直接使用无需任何配置。

## 3. 房间模式 · 局域网（线下聚会）

**断网也能玩**：只要房主的本机开着服务，其他人在同一局域网（连同一个 Wi-Fi / 热点）即可加入。

1. 房主机器运行 `npm start`（服务监听 `0.0.0.0:3000`）。
2. 房主查看启动日志里的「局域网」地址，例如 `ws://192.168.1.23:3000/ws`，
   或在本机命令行用 `ipconfig` 查到自己的 IPv4 地址。
3. 其他人**连同一个局域网**，在手机/电脑浏览器打开 `http://192.168.1.23:3000`
   （把上面的 IP 换成房主实际 IP），即可进入房间页。
4. 输入房间码加入；也可在首页点「搜索房间」自动列出本网段可加入的房间。

**防火墙注意（Windows 常见坑）**：

- 房主的 Windows 防火墙可能拦截 3000 端口的入站连接。首次运行 Node 若弹出「是否允许访问网络」，**务必勾选「专用网络」允许**。
- 若别人连不上，手动放行：Windows 安全中心 → 防火墙 → 高级设置 → 入站规则 → 新建规则 → 端口 → TCP 3000 → 允许。
- 也可临时关闭专用网络防火墙做连通性测试，**测完请恢复**。
- 部分公司/校园网络禁止局域网互访，此时请用「公网模式」或手机热点共享。

## 4. 房间模式 · 公网（异地联网）

> **完整操作步骤见 [`DEPLOY.md`](./DEPLOY.md)**（含 Render / Netlify / Cloudflare Tunnel 三条路线的按钮级步骤与排障表）。

同一套房间服务既能在局域网跑，也能部署到任意支持 WebSocket 的云端。三种路线：

| 路线                                 | 做法                                              | 费用     | 主要缺点                             |
| ------------------------------------ | ------------------------------------------------- | -------- | ------------------------------------ |
| **A · Render 一条龙**（推荐） | 整个仓库部署到 Render，页面与后端一起由 Node 托管 | 免费额度 | 空闲 15 分钟休眠，唤醒约 1 分钟      |
| **B · Netlify + Render**      | 前端静态走 CDN，后端独立部署                      | 免费额度 | 需在`js/config.js` 填一行后端地址  |
| **C · Cloudflare Tunnel**     | 本机`npm start`，隧道映射公网                   | $0       | 电脑必须开机，免费版网址每次重启会变 |

要点：

- 路线 A **零配置**：Node 服务在返回首页时会按访问地址自动注入 `wss://.../ws`，前端直接连上。
- 路线 B 因为页面由纯静态托管提供、没有注入，需在 `js/config.js` 设置 `MJ_PUBLIC_WS_URL`
  （必须是 `wss://` 且以 `/ws` 结尾），**改完务必同步 bump `index.html` 里的 `?v=` 版本号**，
  否则用户端还在吃缓存。
- **只部署纯静态页面是无法使用房间模式的**——房间状态由后端统一保管。

部署后验证：

```bash
curl https://你的域名/health                    # 期望 {"ok":true,"rooms":0}
BASE_URL=https://你的域名 npm run smoke          # 全链路冒烟：建房/加入/抽牌/保密/使用公开
```

仓库已备好 `render.yaml`（Render Blueprint 一键部署）与 `Dockerfile`（任意支持 Docker 的平台通用）。

## 5. 玩法规则

- **建房配置**：房主设定「共享技能池」（从全部技能中勾选）与「每人每局抽卡数」。
- **各自抽卡**：玩家点「抽卡」一次性抽满设定张数；同一玩家的卡**互不重复**。
- **保密**：未使用的卡**只有本人能看到内容**；他人仅看到「已抽 N 张」的牌背。
- **使用公开**：本人点「使用」后，该卡的名称与效果向房间全员公开，并显示在公共牌区。
- **跨玩家可重复**：不同玩家可以抽到相同技能（只有同一人内部不重复）。
- **房主重置**：仅房主可操作，需二次确认。重置会清空所有玩家的手牌与使用状态、
  局数 +1，**保留**玩家名单、技能池、每人抽卡数配置，开新一局。
- **断线重连**：关闭页面 / 临时掉线后，凭本地保存的会话令牌自动恢复原座位与手牌
  （手牌内容仍在，因服务器为权威来源）。

## 6. 部署与运维说明

- **内存存储**：房间数据全部保存在进程内存中，**服务重启即清空所有房间**。
  如需持久化，请自行接入数据库或在重启前导出（当前版本定位为轻量聚会工具，未做持久化）。
- **房间码非凭证**：房间码仅用于「加入」，不提供鉴权；任何拿到房间码且能连上服务的人都能进房。
  公网部署请通过反向代理的访问控制（如 BASIC 认证 / 私有网络）自行加固。
- **协议限制**：单条 WebSocket 消息上限 16 KiB；单房间 2–4 人。
- **纯娱乐声明**：本项目仅用于朋友聚会娱乐，**禁止用于任何赌博或真实金钱交易场景**。

## 7. 技术架构与测试

```
浏览器(HTML/CSS/JS)  ──WebSocket(/ws)──►  Node 服务(server/index.js)
   js/skills.js 共享技能库                  ├─ 静态托管 index.html/CSS/JS
   js/app.js   单机逻辑                    └─ RoomManager(server/room-manager.js)
   js/rooms.js  房间客户端                       · 权威房间状态 · 保密快照 · 断线重连
```

- 前端：纯静态，可上 Netlify；后端：`ws` + Node `http`，同端口提供静态页与 `/ws`。
- 前端无需配置 WS 地址：`server/index.js` 在返回首页时按当前访问地址注入 `ws://` 或 `wss://`。
- 保密由**服务端**保障：每位玩家只收到自己的专属快照（含私牌），他人仅收到牌背数量与已公开的卡。

运行测试（需先 `npm install`）：

```bash
npm test         # node --test，覆盖房间规则与 WebSocket 集成
```

## 微信打不开最新版？

微信内置浏览器缓存很重。立刻刷新可用：

1. 链接后加随机参数，例如 `https://你的域名/?t=1`
2. 或在微信里：右上角 `···` → 刷新
3. 仍旧：微信设置 → 通用 → 存储空间 → 清理缓存

以后每次发版会改 `index.html` 里 CSS/JS 的 `?v=` 版本号，避免继续吃旧资源。
